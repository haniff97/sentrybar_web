Frequently Asked Questions

Everything you need to know about safety, permissions, and system support.

Is fan control and root elevation safe for my Mac? ▼
Yes. SentryBar enforces hardware safety clamps: target RPMs are strictly validated against each fan's factory reported maximum RPM (F{n}Mx). If the helper disconnects or crashes, macOS automatically regains control of the thermal fan curves.
Why are both Accessibility and Input Monitoring permissions required? ▼
In macOS Tahoe, Sequoia, and Sonoma, a CGEventTap in default (blocking) mode requires both Accessibility and Input Monitoring to swallow physical keystrokes. Without Input Monitoring, the tap can listen to events but cannot block them.
How does brightness control work on external non-Apple monitors? ▼
Many third-party HDMI and DisplayPort monitors do not respond to standard DDC/CI over I2C on Apple Silicon. SentryBar implements a zero-flicker software shade overlay (black borderless statusBar window with smooth opacity transitions) so you can dim any display comfortably.
Why do TCC permissions survive app rebuilds in make-app.sh? ▼
Standard ad-hoc code signing creates a new hash (cdhash) every build, causing macOS to revoke permissions. Our build script signs with an identifier-only designated requirement: codesign --force --sign - --identifier local.sysmon.SentryBar, preserving permission grants across rebuilds!
Ready to Run

Get SentryBar on Your Mac

Compile in seconds using native Swift Package Manager or package the self-contained app bundle with persistent TCC designated requirements.

$ git clone https://github.com/haniff97/SentryBar
$ cd SentryBar
# Run directly (development)
$ swift run SystemMonitor
# Print all sensor readings (CLI)
$ swift run SystemMonitor --test
# Build the packaged .app
$ ./scripts/make-app.sh # -> dist/SentryBar.app
$ open dist/SentryBar.app
# Build the DMG installer
$ ./scripts/make-dmg.sh # -> dist/SentryBar.dmg (+ prints SHA-256)
